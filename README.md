# Аналитическая витрина данных для банка

Учебный проект по проектированию небольшого аналитического хранилища данных для банковской аналитики.

## О проекте

Я хотела разобраться, как данные могут проходить путь от отдельных банковских операций до показателей, которые можно использовать для анализа продукта.

Поэтому я самостоятельно спроектировала структуру базы данных, сгенерировала синтетические данные, загрузила их в SQLite и написала SQL-запросы для расчёта основных продуктовых метрик.

Проект показывает полный базовый цикл работы с аналитическими данными: от подготовки структуры и данных до получения готовых показателей.

## Что я сделала

### 1. Подготовила данные

Так как реальные банковские данные недоступны, я использовала синтетические данные и сгенерировала их с помощью Python.

В данных смоделировала несколько сущностей:

- клиентов;
- банковские продукты;
- транзакции;
- даты операций.

В качестве продуктов рассматривались дебетовая карта, кредитная карта и вклад.

Для транзакций использовала такие основные поля, как `transaction_id`, `client_id`, `product_id`, дата операции и сумма.

### 2. Спроектировала структуру DWH

Для хранения данных выбрала звёздную схему.

В центре находится фактовая таблица с транзакциями, которая связана с таблицами-измерениями:

- `clients` — информация о клиентах;
- `products` — информация о продуктах;
- `date` — календарь;
- `transactions` — факты банковских операций.

Такое разделение позволяет не хранить информацию о клиенте или продукте повторно в каждой транзакции и упрощает дальнейший анализ.

### 3. Загрузила данные в SQLite

После подготовки данных загрузила их в SQLite и проверила, что таблицы корректно связаны между собой.

Основную аналитическую часть проекта выполняла с помощью SQL.

### 4. Рассчитала продуктовые метрики

На основе транзакций рассчитала несколько показателей:

**MAU** — количество уникальных активных клиентов за месяц.

**ARPU** — средний доход на одного активного клиента.

**Средний чек** — средняя сумма одной транзакции.

**Retention** — доля клиентов, которые продолжили пользоваться продуктом после первого периода активности.

Метрики рассчитывала с использованием SQL-запросов и агрегирования данных по временным периодам.
